# 2.2 飛行更新驗收

2026 年 10 月 6 日。

## 模型與玩法

根工作實際執行 `npm test`，76／76 項通過。新增 16 項飛行檢查包含 24 組新玩法（3 種玩法×4 張圖×2 組機型參數）完整通關、單次點擊起飛與自動煞停、地面連點保護、左右方向、投遞物理、景點停留、實際返航及取消返航不瞬移。

根工作另執行 GLB 二進位驗收：八個運輸工具／座艙模型、279,668 個 UV 頂點全部在指定格內。飛機外觀為 49,870 個三角形、28 draws、4,164,940 bytes；座艙為 13,636 個三角形、15 draws、3,180,796 bytes。每個 GLB 嵌入一張原 IMG，雜湊相符，必要控制節點保留。模型製作者真實執行 Blender 重建、渲染、重開；根工作也逐一看過成品、座艙及機鼻細節圖。

## 畫面區域

以 Chromium 實際開啟遊戲，量測 stage、相機 viewport、模型的保守投影邊界與可見 UI 長方形。

| 尺寸 | 用途 |
| --- | --- |
| 390×844、375×667 | 直向手機 |
| 844×390、568×320 | 橫向手機，包含最小高度 |
| 768×1024、1024×768 | 平板直向與橫向 |
| 1440×900 | 桌面 |

各尺寸都檢查幼兒／家長模式，以及儀表收合／展開，共 28 組。所有組合模型 visible／contained／inDepth 均通過，完整模型投影與標題、任務提示、控制列沒有交集，也沒有水平溢出。舞台長方形與 `#flight-window`、實際 renderer 尺寸一致；儀表展開時也等待 Canvas 2D 真正完成繪製，避免只檢查 click 之後的舊版面。

家長模式在 568×320 且展開儀表時，仍保留 340×201 的飛行區域；控制列置於右側，可在列內捲動。390×844 幼兒預設視窗為 390×553，三顆操作鈕在視窗下方。選單飛機也檢查完全位於旅程卡片上方，出發按鈕維持可見。

完整逐組結果：[flight-upgrade-layout-verification.json](flight-upgrade-layout-verification.json)。

可重跑：

```powershell
./scripts/verify-flight-layout.ps1 -BaseUrl 'http://localhost:5178/flight/'
```

需要已啟動的遊戲、Node.js／npx 與 Playwright CLI 瀏覽器。函式先讀當前選單，再透過真實選單選擇模式、按出發、展開儀表；沒有用直接設定座標或假裝模型可見。

## 快取更新

先在 localhost:5191 真實安裝 2.1 版 Worker，確認當時只有四個活動、沒有獨立飛行視窗。改為 2.2 正式建置後重載，在選單觀察到新 Worker 啟用及閒置刷新；新模型實際讀到 49,870 個三角形、七個活動與保護視窗，完整模型可見。更新程式在飛行途中只記住待更新狀態，回選單才重載。

這些是瀏覽器尺寸與確定性物理驗收。尚未在使用者的實體 iPhone、iPad 或 Android 裝置量測 FPS；畫質設定仍有省電模式。地景為原創縮尺場景，物理為可檢驗的簡化模型。
